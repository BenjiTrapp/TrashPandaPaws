# Dependencies of the agent service only.
#
# Deliberately separate from software/requirements.txt, which is the C2's and
# must not grow: the project's hard promise is that the existing C2 and beacon
# keep working with no model attached and nothing new installed. The agent is
# a separate process (spec §7) with its own image (Dockerfile beside this
# file), so what it needs is its own business.
#
# The LLM transport and the C2 client deliberately do *not* appear here. Both
# speak JSON over HTTPS and use `requests`, which the C2 already declares, so
# the agent works the moment it is configured rather than after a second
# install step. aiohttp is here because this is the one place a hand-rolled
# alternative would be worse: an authenticated HTTP server is not something to
# write from scratch for a security tool.

aiohttp>=3.9.0

# Cron parsing for the scheduler. Hand-rolling five fields is tempting and
# about eighty lines, and the reason not to is the day-of-month/day-of-week
# interaction: when both are set, cron means OR, not AND — `0 0 13 * 5` fires
# every Friday *and* on the 13th. Getting that wrong fires a campaign outside
# an agreed testing window, which is a rules-of-engagement problem rather
# than an inconvenience. Pure Python, no transitive dependencies.
croniter>=1.4.0

# Inherited from the C2's set, listed so this file stands alone.
requests>=2.31.0
pyyaml>=6.0
